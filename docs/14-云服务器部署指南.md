## 0. 部署形态与全景

### 0.1 目标架构

一台云服务器，用 `docker/docker-compose.yml` 拉起 6 个容器：

```
                        公网
                          │
                    ┌─────┴─────┐  安全组只放行 22 / 80 / 443
                    │  云服务器  │
                    └─────┬─────┘
                          │
        ┌─────────────────┴──────────────────┐
        │            Docker 网络              │
        │                                    │
        │  frontend (nginx :80)              │  ← 静态资源 + /api、/static/uploads 同源反代
        │      │                             │
        │      ├──► backend (Spring :8080)   │  ← 唯一硬依赖 MySQL
        │      │        │                    │
        │      │        ├──► mysql   :3306   │  ← 数据卷 mysql_data（首次自动灌 schema+data）
        │      │        ├──► redis   :6379   │  ← 热度排行 ZSet
        │      │        ├──► rabbitmq:5672   │  ← 删店延时清理（TTL+DLX）
        │      │        └──► elasticsearch :9200 │ ← 关键词检索
        └────────────────────────────────────┘
```

### 0.2 端口与暴露面

| 服务 | 容器端口 | compose 默认映射到宿主机 | 公网是否应可达 |
|---|---|---|---|
| frontend (nginx) | 80 | `8081` | ✅ 是（本文改为 80 / 或经宿主机 nginx） |
| backend | 8080 | `8080` | ⚠️ 可选（同源反代后无需暴露） |
| MySQL | 3306 | `3306` | ❌ **绝对不可以** |
| Redis | 6379 | `6379` | ❌ **绝对不可以**（默认无密码） |
| RabbitMQ | 5672 / 15672 | `5672` / `15672` | ❌ 不可以（默认 guest/guest） |
| Elasticsearch | 9200 | `9200` | ❌ **绝对不可以**（`xpack.security.enabled=false`，无认证） |

> **这是本指南最重要的一节。** compose 为了本地联调方便，把中间件端口全部发布到宿主机。云服务器的公网 IP 一旦配上宽松的安全组，等于把**无密码的 Redis、无认证的 ES、guest/guest 的 RabbitMQ** 直接挂到互联网上，通常在数小时内就会被扫到并利用（挖矿、勒索、数据泄露）。
> 处置见 **§4**（compose 绑定到 `127.0.0.1` + 安全组最小放行，两层都要做）。

### 0.3 内存账（决定选多大机器）

稳态常驻（单机跑全部容器）：

| 组件 | 内存占用（约） |
|---|---|
| Elasticsearch（`ES_JAVA_OPTS=-Xms512m -Xmx512m`） | 1.0 – 1.3 GB（堆 512m + 堆外/Lucene） |
| MySQL 8 | 350 – 500 MB |
| backend JVM（`-Xms256m -Xmx512m`） | 500 – 700 MB |
| RabbitMQ | 150 – 250 MB |
| Redis + nginx | < 80 MB |
| 系统 + Docker 守护进程 | 300 – 500 MB |
| **合计** | **约 2.6 – 3.5 GB** |

另有**构建期**峰值：Maven 打 jar（编译 + 依赖）与 Node 构建前端会额外吃掉 1 – 1.5 GB。构建与运行不同时发生，但都发生在同一台机器上。

结论：**2C4G 是能跑起来的底线（必须配 swap，且首次构建会比较痛苦）；4C8G 是推荐配置**，构建顺滑、留有余量。

## 1. 购买与初始化云服务器

### 1.1 选型建议

| 项 | 建议 | 说明 |
|---|---|---|
| CPU / 内存 | **4 核 8 GB（推荐）** / 2 核 4 GB（最低） | 见 §0.3 内存账 |
| 系统盘 | **40 GB+ 高效云盘/SSD** | 镜像约 3.5 GB + 构建缓存 + 数据库增长 |
| 操作系统 | **Ubuntu 22.04 LTS 或 24.04 LTS** | 本文命令以 Ubuntu 为准；Debian 12 同理 |
| 地域 | 国内用户选国内节点（**域名需 ICP 备案**）；想免备案选香港/新加坡等海外节点 | 备案走云厂商的备案系统，通常 3–20 个工作日 |
| 带宽 | 按量/固定 3–5 Mbps 起 | 图片走 `local` 存储会吃服务器带宽；流量大建议改 OSS（`STORAGE_TYPE=oss`，见 §3 的 `.env` 模板） |
| 公网 IP | 必须有 | |

### 1.2 安全组（在云厂商控制台设置）

**只放行这三个入方向端口**，其余全部拒绝：

| 端口 | 用途 | 建议限制来源 |
|---|---|---|
| 22 | SSH | **仅你的固定 IP**（比开放全网安全得多） |
| 80 | HTTP（证书签发 + 跳转 HTTPS） | 0.0.0.0/0 |
| 443 | HTTPS | 0.0.0.0/0 |

> 出方向保持默认全放行（拉取镜像、下载依赖需要）。
> **不要**为了「方便调试」把 3306/6379/5672/15672/9200/8080 加进安全组。

**未备案阶段（只有 IP、没域名）额外要放一条**：前端容器的端口映射是 `8081:80`（见 §0.2），所以要临时放行 **TCP 8081**、来源 `0.0.0.0/0`，否则浏览器打不开 `http://<公网IP>:8081`——现象是"无法访问此网站"，而服务器上 `curl 127.0.0.1:8081` 却返回 200，很容易误判成服务没起来。等域名备案完成、按 §8.2 上 443 之后，**这条规则要删掉**。（另一条路见 §8.1：把映射改成 `80:80` 并放行 80。）

### 1.3 首次登录与基础加固

> **先确认你以什么身份登录（`whoami`）。** 本文命令按 **root** 书写。腾讯云 Ubuntu 镜像默认登录用户是 **`ubuntu`**（有免密 sudo，root 直连通常被禁），此时：
> - 所有特权命令前面加 **`sudo`**：`apt` / `timedatectl` / `fallocate` / `mkswap` / `swapon` / `sysctl` / `usermod` / `get.docker.com` 安装脚本 / 写 `/etc/` 与 `/usr/` 的命令；
> - `echo ... >> /etc/xxx` 这类**重定向**改成管道：`echo ... | sudo tee -a /etc/xxx`（`sudo` 只提升命令的权限，不提升 shell 重定向的权限，直接写会 `Permission denied`）；
> - §1.3 第 3 步「建非 root 运维账号」**可跳过**（`ubuntu` 本身就是这个角色）；
> - §2 拉代码前执行 `sudo chown ubuntu:ubuntu /opt`，把部署目录交给自己，后面 git/构建就不用再 sudo。
>
> 输出 `root` 就照抄本文命令，输出 `ubuntu` 就按上面的规则加 `sudo`。

```bash
# 从你的电脑登录（把 <公网IP> 换成实际地址）
ssh root@<公网IP>              # 登录用户是 ubuntu 时：ssh ubuntu@<公网IP>

# 1) 系统更新
apt update && apt upgrade -y

# 2) 时区设为上海（与后端 TZ=Asia/Shanghai、Jackson 时区一致）
timedatectl set-timezone Asia/Shanghai
timedatectl                      # 确认输出 Time zone: Asia/Shanghai (CST, +0800)

# 3) 建一个非 root 运维账号（可选但建议）
adduser deploy
usermod -aG sudo deploy
# 之后用 deploy 登录，需要 root 时加 sudo
```

### 1.4 配置 swap（2C4G 必做，4C8G 建议做）

构建镜像时内存峰值容易被 OOM Killer 打断（典型现象：`mvn` 或 `npm` 进程莫名被杀，报 `Killed`）。

```bash
# 建 2GB swap（4C8G 机器建 2GB 也够；2C4G 建议 4GB）
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab   # 开机自动挂载

free -h                                           # 确认 Swap 一行非 0
```

### 1.5 调整内核参数（**Elasticsearch 必需**）

ES 默认要求 `vm.max_map_count >= 262144`，绝大多数云主机默认只有 65530，不改的话 ES 容器会**反复重启**并报：

```
max virtual memory areas vm.max_map_count [65530] is too low, increase to at least [262144]
```

```bash
sysctl -w vm.max_map_count=262144
echo 'vm.max_map_count=262144' >> /etc/sysctl.conf   # 永久生效
sysctl -p
```

### 1.6 安装 Docker 与 compose 插件

```bash
# 官方一键脚本（Ubuntu/Debian）
curl -fsSL https://get.docker.com | sh

# 校验：compose 已被 v2 插件形式自带
docker --version            # Docker version 27.x / 28.x
docker compose version      # Docker Compose version v2.x

# 让非 root 用户也能用 docker（重登生效）
usermod -aG docker $USER
# 然后退出 SSH 重新登录；或先全程用 sudo docker
```

> **国内节点拉不动镜像**时，给 Docker 配镜像加速（在云厂商控制台或 `/etc/docker/daemon.json` 里加 `registry-mirrors`），配好后 `systemctl restart docker`。腾讯云的内网加速地址见 **§1.7**。
> 注意 `docker.elastic.co`、`maven`、`node` 这类官方源通常不在国内镜像站覆盖范围内，网络不通时可能需要配代理。

### 1.7 云厂商适配（以腾讯云为例）

本文命令与厂商无关，只有几处术语与地址需要按厂商替换：

| 项 | 腾讯云 | 阿里云 |
|---|---|---|
| 网络访问控制 | CVM 叫**安全组**；轻量应用服务器（Lighthouse）叫**防火墙**（在实例详情页） | 统称安全组 |
| Docker 镜像加速 | 内网源 `https://mirror.ccs.tencentyun.com` | 用容器镜像服务分配的专属加速地址 |
| 自研系统镜像 | **TencentOS Server**（RHEL 系，`dnf`/`yum`） | **Alibaba Cloud Linux**（同为 RHEL 系） |

腾讯云 Docker 加速配置：

```bash
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
}
EOF
systemctl restart docker
```

- **别选自研系统镜像**（TencentOS / Alibaba Cloud Linux）：本文命令全是 apt/Debian 系，选它们得逐条翻译包管理命令。选 **Ubuntu Server 24.04 LTS 64位**（公共镜像）。
- **别选应用镜像**（宝塔 / WordPress / LNMP 一键包等）：本文从纯净系统装起，多一层面板只增加内存占用与排障难度，4G 内存的机器上尤其不划算。
- 镜像加速**对 `docker.elastic.co`、Maven 中央仓库、npm 官方源不生效**，这几个源的连通性要单独确认。
- 大陆地域（如上海）要用域名对外，**必须先完成 ICP 备案**（在云厂商备案系统提交，通常数天到两三周）。未备案期间域名访问 80/443 会被拦；可先用 `http://<公网IP>:8081`（本栈前端默认映射端口）验证功能。
- **4 核 4G 及以下规格**，建议把镜像构建放到本地或 CI 完成后推到容器镜像服务（腾讯云 **TCR** 个人版免费），服务器上只 `docker pull`，避免构建期内存峰值顶穿（见 §0.3、§11 的 `Killed` 条目）。

## 2. 拉取代码

仓库是 **public**，无需任何凭据：

```bash
mkdir -p /opt && cd /opt
git clone https://github.com/HRALH/TasteLink.git
cd TasteLink

# 确认在你期望的分支（默认 main）
git log --oneline -3
```

> 如果将来仓库转私有：用 SSH 部署密钥（`ssh-keygen` → 把公钥加到仓库 Deploy keys），或 `git clone https://<token>@github.com/...`。**不要把 token 写进任何会提交的文件。**

**关键：必须在干净的第 2 步之后构建。** 仓库内**没有 `.dockerignore`**，而 `docker/Dockerfile.frontend` 里有一句 `COPY frontend/ ./`（在 `npm ci` 之后执行）——如果 `frontend/node_modules` 已存在，它会被整份拷进镜像，**覆盖掉刚装好的 Linux 依赖**（把本地平台的构建产物、`@rolldown/binding-*` 等原生模块带进来），导致 `npm run build` 失败。

- 云端全新 clone **天然没有** `node_modules`，所以默认流程没问题；
- 但如果你在服务器上跑过 `npm install`（例如为了本地调试），务必先删掉再构建：`rm -rf frontend/node_modules frontend/dist backend/target`；
- 想根治，见 **§10.3(b)**（补一个 `.dockerignore`）。

## 3. 创建 `.env`

`.env` 已被 `.gitignore` 的 `.env` 规则排除，**不会入库**。在仓库根目录执行：

> **位置必须是仓库根的 `/opt/TasteLink/.env`，不能放到 `docker/` 下。** Compose 的 `${VAR}` 插值只从「当前工作目录 + 项目目录」读 `.env`，而本文所有命令都带 `--project-directory .`（并被 `tlc` 别名固定），两者都指向仓库根，`docker/.env` 不会被读取——后果不对称：`JWT_SECRET` 会直接报「必填」中断，`DB_PASSWORD` 却会静默落回 compose 的默认值 `rootpass`，看起来一切正常。写在仓库根后，全部 compose 命令无需再加 `--env-file`。

```bash
cd /opt/TasteLink

# 先生成两个随机密钥，复制输出备用
openssl rand -base64 32   # → JWT_SECRET
openssl rand -base64 24   # → DB_PASSWORD
```

```bash
cat > .env <<'EOF'
# ===== MySQL =====
DB_NAME=tastelink
DB_PASSWORD=把上面第二个输出粘在这里

# ===== 后端 =====
SPRING_PROFILES_ACTIVE=local
JWT_SECRET=把上面第一个输出粘在这里

# ===== 文件存储 =====
STORAGE_TYPE=local
# ⚠️ 必须改成「浏览器能访问到的后端地址」，否则上传的图片 URL 会以 http://localhost:8080
#    的绝对地址写进数据库，只有服务器自己打得开（见 §8.3）
STORAGE_PUBLIC_BASE_URL=https://你的域名

# 前端真实域名（走同源反代时理论上不触发 CORS，仍建议显式配置兜底）
CORS_ORIGINS=https://你的域名

# ===== v2 三阶段特性开关（true = 全功能；任一 false 会降级）=====
RANK_CACHE_ENABLED=true
RABBIT_ENABLED=true
SEARCH_ENABLED=true

# ===== RabbitMQ（改了这里，15672 管理界面也用这套账号）=====
RABBITMQ_USER=tastelink
RABBITMQ_PASSWORD=再生成一个强密码填这里

# ===== OSS（仅当 STORAGE_TYPE=oss 时填；用 local 存储就全部留空/不要这些行）=====
# OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
# OSS_AK=
# OSS_SK=
# OSS_BUCKET=
# OSS_DOMAIN=
EOF

chmod 600 .env     # 只有属主可读
```

`.env` 里各变量的完整含义与默认值见 `docs/08 §6 环境变量总表`。上面**每一项都是要改的**：

| 变量 | 不改会怎样 |
|---|---|
| `DB_PASSWORD` | 默认 `rootpass`，弱口令 |
| `JWT_SECRET` | compose 里是 `:?` 必填，不填**直接启动失败**；用占位值等于谁都能伪造 token |
| `STORAGE_PUBLIC_BASE_URL` | 图片 URL 变成 `http://localhost:8080/...`，**除了服务器自己，所有人的图片都是坏链** |
| `CORS_ORIGINS` | 跨域被拒 |
| `RABBITMQ_USER/PASSWORD` | 默认 `guest/guest`；注意 `guest` 账号在网络接口上默认受限，自定义账号更稳 |

## 4. 收紧对外暴露面（**上线前必做**）

把中间件端口从「发布到公网」改成「只绑在本机回环」。编辑 `docker/docker-compose.yml`，找到对应 `ports` 行改成下面这样：

```yaml
  mysql:
    ports: ["127.0.0.1:3306:3306"]        # 原: ["3306:3306"]

  redis:
    ports: ["127.0.0.1:6379:6379"]        # 原: ["6379:6379"]

  rabbitmq:
    ports: ["127.0.0.1:5672:5672", "127.0.0.1:15672:15672"]   # 原: ["5672:5672", "15672:15672"]

  elasticsearch:
    ports: ["127.0.0.1:9200:9200"]        # 原: ["9200:9200"]

  backend:
    ports: ["127.0.0.1:8080:8080"]        # 原: ["8080:8080"]（同源反代后无需对外暴露）

  frontend:
    ports: ["8081:80"]                     # 若要直接用 80 对外，改成 ["80:80"]，见 §8.1
```

> 这些容器之间的访问走的是 Docker 内部网络（用服务名 `mysql`/`redis`/`backend` 等），**与宿主机端口映射无关**，所以收紧映射不影响应用功能。
> 绑 `127.0.0.1` 之后，即使安全组配错，公网也连不上这些端口——这是第二道防线，两道都要有。
>
> 可选加固（按需，不影响本文其余步骤）：
> - Redis 加密码：给 `redis` 服务加 `command: redis-server --requirepass <强密码>`，**并在 `backend` 服务的 `environment` 里补一行** `REDIS_PASSWORD: ${REDIS_PASSWORD:-}`（compose 默认没把它传进容器，只在 `.env` 写是不生效的），然后在 `.env` 加 `REDIS_PASSWORD=<同一密码>`。
> - ES 开安全：`xpack.security.enabled=true` 并配置账号密码、同步 `ES_URIS` 加 `http://user:pass@host:9200`；本地存储与检索都走 Spring 配置，改动面比看上去大，单机内网部署可先用 `127.0.0.1` 绑定兜住。

改完后验证一下 compose 文件仍然合法：

```bash
docker compose --project-directory . -f docker/docker-compose.yml config >/dev/null && echo "compose OK"
```

## 5. 构建并启动全栈

**必须在仓库根目录、且带 `--project-directory .`**（compose 的 build context 和挂载路径都以仓库根为基准；漏了这个参数会找不到 `backend/pom.xml`）：

```bash
cd /opt/TasteLink

# 首次：构建镜像并后台拉起全部 6 个容器
docker compose --project-directory . -f docker/docker-compose.yml up -d --build
```

首次构建耗时参考：**4C8G 约 5–12 分钟**（Maven 拉依赖 + Node 装依赖占大头）；2C4G 会更久，耐心等，别中断。

建议把这条命令记成别名，后面运维会反复用：

```bash
alias tlc='docker compose --project-directory /opt/TasteLink -f /opt/TasteLink/docker/docker-compose.yml'
# 之后：tlc ps / tlc logs -f backend / tlc restart backend / tlc down
echo "alias tlc='docker compose --project-directory /opt/TasteLink -f /opt/TasteLink/docker/docker-compose.yml'" >> ~/.bashrc
```

### 5.1 启动顺序与等待

compose 里 backend 只对 `mysql` 做了 `service_healthy` 门控，Redis/RabbitMQ/ES 是「先起就行」（应用侧懒连接 + 可降级）。所以：

```bash
# 看容器状态，mysql 应显示 (healthy)，其余 Up
tlc ps

# 跟后端日志，等到出现 "Started TasteLinkApplication"
tlc logs -f backend
```

后端启动成功的标志（日志末段）：

```
... Started TasteLinkApplication in xx.xxx seconds
```

> ES 首启动较慢（30–60s），启动期间后端不会报错——`ShopIndexInitializer` 探测不到 ES 就静默跳过，等 `SEARCH_REBUILD_CRON`（默认 10 分钟）第一次全量重建后检索才真正生效。想立刻生效见 §7.4。

### 5.2 数据库自动初始化说明

`docker-compose.yml` 把 `backend/src/main/resources/db/schema.sql` 与 `data.sql` 挂进了 MySQL 容器的 `/docker-entrypoint-initdb.d/`，**仅在 `mysql_data` 数据卷为空的首次启动时自动执行**。

- 首次 `up` 之后，表结构与种子数据（分类、店铺、城市）就绪，无需手动导入；
- 之后**改了 `schema.sql` 也不会重跑**——要么手工执行 DDL，要么 `tlc down -v` 清卷重来（**会删掉全部数据与上传的图片**，生产环境务必先备份，见 §9.2）；
- `schema.sql` / `data.sql` 开头的 `SET NAMES utf8mb4;` **不要删**：MySQL 官方镜像容器 locale 是 `C`，initdb 目录里的 SQL 由容器内 `mysql` 客户端导入，客户端字符集可能落到 `latin1`，会把 UTF-8 中文按 latin1 解释再转存成 utf8mb4——**一个汉字变两个，全库乱码**。compose 里的 `--character-set-server=utf8mb4` 只管服务端，管不到这一步。发现中文乱码时先确认这两句还在。

### 5.3 首次构建实测记录（2026-09-20，腾讯云 4C4G / Ubuntu 24.04）

## 6. 提权一个管理员账号

后台功能（编辑店铺、点评治理、举报队列）需要 `role=ADMIN`。流程是：**先在前端注册**，再改库提权。

```bash
# 1) 浏览器打开站点，注册一个普通账号，例如 alice

# 2) 进 MySQL 容器执行 UPDATE（密码用 .env 里的 DB_PASSWORD）
docker exec -it tastelink-mysql \
  mysql -uroot -p"$(grep '^DB_PASSWORD=' /opt/TasteLink/.env | cut -d= -f2-)" tastelink \
  -e "UPDATE t_user SET role='ADMIN' WHERE username='alice'; SELECT id,username,role FROM t_user WHERE username='alice';"

# 3) 前端退出重新登录（role 由 JWT 携带，旧 token 里还是 USER）
```

重新登录后顶栏出现管理入口，可直接访问 `/admin/shops`、`/admin/reviews`。

> 也可以不重建容器直接进 mysql 客户端：`docker exec -it tastelink-mysql mysql -uroot -p tastelink`，交互式敲 SQL。

## 8. 对外发布：域名 + HTTPS

### 8.1 最简路径（只用 IP 和 80 端口）

1. 把 `docker/docker-compose.yml` 里 frontend 的映射改成 `["80:80"]`；
2. `.env` 里 `STORAGE_PUBLIC_BASE_URL=http://<公网IP>`、`CORS_ORIGINS=http://<公网IP>`；
3. `tlc up -d`（改了端口映射需重建容器）。

浏览器直接开 `http://<公网IP>` 即可。**仅建议用于验证阶段**——没 HTTPS，JWT 明文传输，且微信/现代浏览器会给不安全警告。

### 8.2 推荐路径（域名 + 宿主机 nginx + Let's Encrypt）

保留 compose 里 frontend 的 `8081:80` 不动，在宿主机上装 nginx 做 80/443 入口，证书交给 certbot：

```bash
# 1) 域名解析：在域名服务商处把 A 记录指到 <公网IP>（例如 @ 和 www）

# 2) 宿主机装 nginx + certbot
apt install -y nginx certbot python3-certbot-nginx
rm -f /etc/nginx/sites-enabled/default

# 3) 写站点配置（先用 HTTP，好让 certbot 校验）
cat > /etc/nginx/sites-available/tastelink <<'EOF'
server {
    listen 80;
    server_name 你的域名 www.你的域名;

    client_max_body_size 20m;      # 与后端 multipart max-request-size 对齐，否则上传大图 413

    location / {
        proxy_pass http://127.0.0.1:8081;     # 转到 frontend 容器
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
ln -sf /etc/nginx/sites-available/tastelink /etc/nginx/sites-enabled/tastelink
nginx -t && systemctl reload nginx

# 4) 验证 HTTP 能打开页面后，签发并自动装上证书（certbot 会改写配置加 443 与跳转）
certbot --nginx -d 你的域名 -d www.你的域名
```

> 前端容器的 nginx 已经把它们收到的 `/api/` 与 `/static/uploads/` 转发给 backend，所以宿主机只要整站转给 `127.0.0.1:8081` 就够了，**不需要**再单独配 `/api` 规则。前后端同源，天然没有跨域问题。
>
> `certbot` 会自动续期（systemd timer）；手动验证：`certbot renew --dry-run`。

### 8.3 ⚠️ 图片 URL 的坑（最容易上线后才发现）

`STORAGE_TYPE=local` 时，上传图片会在**入库那一刻**把 `STORAGE_PUBLIC_BASE_URL + /static/uploads/...` 拼成**绝对地址**存进 `t_review_image.url`。这意味着：

- 如果先用了 `http://localhost:8080` 上传了图片，后来才改成域名，**旧图片的 URL 仍是 localhost**，别人看到的全是坏链；
- 修复办法是直接改库（**备份后**执行）：

```bash
docker exec -it tastelink-mysql \
  mysql -uroot -p"$(grep '^DB_PASSWORD=' /opt/TasteLink/.env | cut -d= -f2-)" tastelink \
  -e "UPDATE t_review_image SET url=REPLACE(url,'http://localhost:8080','https://你的域名'); \
      UPDATE t_user SET avatar_url=REPLACE(avatar_url,'http://localhost:8080','https://你的域名') WHERE avatar_url LIKE 'http://localhost:8080%'; \
      UPDATE t_shop SET cover_url=REPLACE(cover_url,'http://localhost:8080','https://你的域名') WHERE cover_url LIKE 'http://localhost:8080%';"
```

- **更省心的做法**：上线前就把 `STORAGE_PUBLIC_BASE_URL` 定为最终域名（本文 §3 的模板就是这么写的）；或者改用 OSS（§3 模板里的 `STORAGE_TYPE=oss` 与 `OSS_*` 变量），图片地址与站点解耦。

```bash
mkdir -p /opt/TasteLink/scripts
cat > /opt/TasteLink/scripts/backup.sh <<'SCRIPT'
#!/usr/bin/env bash
# TasteLink 每日备份：MySQL 逻辑备份 + 上传图片卷打包
set -euo pipefail
ROOT=/opt/TasteLink
BACKUP=/opt/backup
mkdir -p "$BACKUP"
DB_PASS="$(grep '^DB_PASSWORD=' "$ROOT/.env" | cut -d= -f2-)"
STAMP="$(date +%F)"

docker exec tastelink-mysql mysqldump -uroot -p"$DB_PASS" \
  --single-transaction --routines tastelink > "$BACKUP/tastelink-$STAMP.sql"

docker run --rm -v tastelink_backend_uploads:/data:ro -v "$BACKUP":/backup \
  alpine tar czf /backup/uploads-$STAMP.tar.gz -C /data .

# 只保留最近 14 天
find "$BACKUP" -name 'tastelink-*.sql' -mtime +14 -delete
find "$BACKUP" -name 'uploads-*.tar.gz' -mtime +14 -delete
echo "[$(date '+%F %T')] backup done: tastelink-$STAMP.sql"
SCRIPT
chmod +x /opt/TasteLink/scripts/backup.sh

# 挂进 cron：每天 03:30 执行
cat > /etc/cron.d/tastelink-backup <<'EOF'
30 3 * * * root /opt/TasteLink/scripts/backup.sh >> /var/log/tastelink-backup.log 2>&1
EOF
```

> 卷名默认是 `<项目目录名>_backend_uploads`；用 `docker volume ls | grep backend_uploads` 确认实际名字。
> **异地备份**：云厂商的对象存储（`ossutil`/`aws s3`）比只留本机安全——机器挂了本地备份也一起没了。

## 10. 已知限制（当前版本如实说明）

### 10.1 中文检索分词较弱（IK 未装）

标准 ES 镜像不带 IK 插件，中文连续词命中≈`LIKE`。补装（**不需要改应用代码，但需重建索引**）：

```bash
docker exec -it tastelink-elasticsearch \
  bin/elasticsearch-plugin install analysis-ik
tlc restart elasticsearch
# 然后重建索引：删掉旧索引，等 ScheduledShopReconcile（默认 10 分钟）重灌
curl -XDELETE http://127.0.0.1:9200/tastelink-shop
```

> 更彻底的做法是把索引 mapping 指定为 `ik_max_word`/`ik_smart`——这需要改 `ShopDoc` 的 mapping 定义（`ShopIndexInitializer`），属于代码改动。

### 10.2 ES 与 MySQL 是「定时全量重建」同步，不是实时

Canal binlog 增量同步未部署，`ScheduledShopReconcile`（默认 10 分钟）全量重建是唯一同步源。**改店/删店后检索结果最多陈旧 10 分钟。**

### 10.3 构建环境的两处可选改动（实测均非必须）

**(a) 前端构建镜像的 Node 版本偏低**

`docker/Dockerfile.frontend` 第 6 行是 `ARG NODE_IMAGE=node:20-alpine`。而 `vite 8.2.2` / `rolldown` / `oxlint` 的 `engines` 要求是 `^20.19.0 || >=22.12.0`——Node 20 恰好卡在下限、且官方已于 2026 年 4 月 EOL。若该 tag 解析到的版本低于 20.19，`npm run build` 会直接报 Node 版本不受支持。

> 实测（见 §5.3）：该 tag 当前解析到 20.19.x，满足下限、构建通过，故**非必须**；但 Node 20 已 EOL，仍建议对齐本地与 CI 的 24。

建议改为与本地开发、CI 一致的 24：

```dockerfile
ARG NODE_IMAGE=node:24-alpine     # 原: node:20-alpine
```

**(b) 缺 `.dockerignore`（构建上下文过大 + 脏 node_modules 污染镜像）**

仓库根目录没有 `.dockerignore`，`context: .` 会把 `.git`、`frontend/node_modules`（**本地实测 249 MB**）、`backend/target` 全部塞进构建上下文，既慢又危险（见 §2 的 `COPY frontend/ ./` 覆盖问题）。

新建 `/opt/TasteLink/.dockerignore`：

```
.git
.github
docs
frontend/node_modules
frontend/dist
backend/target
.env
**/*.log
**/data/uploads/
```

> `.env` 一行尤其重要：它确保**密钥不会被 `COPY` 进镜像层**。

> 注意：云端服务器上的全新 clone 天然没有 `node_modules` / `target`，所以这条**不影响服务器构建**（实测见 §5.3）；它的收益在本机带 `node_modules` 构建时——既省 249MB 上下文上传，又避免 `COPY frontend/ ./` 用 Windows 产物覆盖容器内已装好的 Linux 依赖。

### 10.4 单点部署的固有取舍

单机跑全部组件 = 简单但无冗余：机器故障即全站不可用；ES/MySQL 与业务抢同一份 CPU 内存。流量上来后的自然演进方向是「数据库与 ES 拆到独立实例 / 中间件托管化 / 应用多副本 + 负载均衡」，这超出本文范围。

## 11. 排错速查

| 现象 | 原因 / 处置 |
|---|---|
| `docker compose up` 报找不到 `backend/pom.xml` 或路径错乱 | 漏了 `--project-directory .`。必须在仓库根执行，见 §5 |
| ES 容器反复重启，日志 `vm.max_map_count [65530] is too low` | 宿主机内核参数未调，执行 §1.5 后 `tlc up -d` 重建容器 |
| 构建镜像时 `mvn` / `npm` 进程被杀，报 `Killed` | 内存不足触发 OOM Killer。配 swap（§1.4）、加大规格，或先 `tlc down` 释放 MySQL/ES 内存再构建 |
| 后端启动失败 `Communications link failure` | MySQL 未就绪或密码不一致。`tlc ps` 看 mysql 是否 `healthy`；确认 `.env` 的 `DB_PASSWORD` 与容器内 `MYSQL_ROOT_PASSWORD` 同源（compose 里两者用的是同一个变量） |
| 前端能开，接口全 404 / 502 | backend 容器没起来或崩了：`tlc logs backend`。同源反代是 frontend nginx → `backend:8080`，backend 挂则全站接口不可用 |
| 图片 404，其他功能正常 | `STORAGE_PUBLIC_BASE_URL` 与浏览器实际访问的地址不一致（local 存储拼绝对 URL）。见 §8.3 |
| 构建后端镜像秒失败：`useradd: UID 1000 is not unique` | 新版 `eclipse-temurin` 基础镜像自带 UID 1000 的 `ubuntu` 用户，Dockerfile 里不能再硬编码 `-u 1000`（见 §5.3） |
| 上传图片报权限错误（后端日志 `Permission denied`） | `/app/data/uploads` 属主是 root。容器内 `ls -ld /app/data/uploads` 应显示 `tastelink`；否则镜像缺 `mkdir + chown` 那一步（见 §5.3） |
| 页面能开，但中文全是 `è¾£åºœ` 这类乱码 | 建库时按 latin1 导入了 UTF-8 种子数据（一个汉字变两个）。确认两个 SQL 开头的 `SET NAMES utf8mb4;` 在，再 `tlc down -v` + `tlc up -d` 重灌；浏览器写入的数据走 JDBC，不受影响（见 §5.2） |
| 上传大图报 413 | 入口 nginx 的 `client_max_body_size` 太小（默认 1m）。宿主机 nginx 与容器 nginx 都要 ≥20m；后端限制为单文件 10MB / 单请求 20MB |
| 页面能开但没有数据（首页热门为空） | 首次建库时 `data.sql` 没执行成功。`docker exec -it tastelink-mysql mysql -uroot -p tastelink -e "select count(*) from t_shop;"` 确认；为 0 则检查数据卷是否为空、init 脚本是否挂载正确 |
| 点赞后热榜排序不变 | Redis 未连通（应用已自动降级 MySQL 排序，功能不报错）。按 §7.3 检查 |
| 删店后数据仍在 | 有 5 秒延时窗口（正常）；若一直不删，检查 RabbitMQ 与 `RABBIT_ENABLED`。对账调度（默认每 2 分钟）也会兜底物理清理 |
| 中文关键词搜不到 | IK 未装（§10.1） |
| 前端改了 `.env` 不生效 | `VITE_API_BASE_URL` 是**构建期**变量（compose 的 build args 注入），改完要 `tlc up -d --build` 重建镜像；运行期环境变量对它无效 |
| `docker compose build` 卡在 `COPY frontend/ ./` 很久 | 上下文过大（无 `.dockerignore`，§10.3b） |
| 国内服务器 `docker pull` 超时 | 配镜像加速；`docker.elastic.co` 等源需自行解决网络（代理或预拉取导入） |

## 附录 A：一键自检脚本

存成 `/opt/TasteLink/scripts/selfcheck.sh`（自建目录），`bash scripts/selfcheck.sh` 执行：

```bash
#!/usr/bin/env bash
# TasteLink 部署自检：容器状态 + 关键接口 + 中间件连通性
set -uo pipefail
cd "$(dirname "$0")/.."
DC="docker compose --project-directory . -f docker/docker-compose.yml"
ok(){ echo "  ✅ $1"; }
bad(){ echo "  ❌ $1"; FAIL=1; }
FAIL=0

echo "== 容器状态 =="
$DC ps

echo "== 接口探活 =="
code=$(curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8080/actuator/health)
[ "$code" = "200" ] && ok "backend /actuator/health 200" || bad "backend health 返回 $code"

body=$(curl -s http://127.0.0.1:8080/api/v1/home)
echo "$body" | grep -q '"code":0' && ok "GET /home code=0" || bad "GET /home 异常: $(echo "$body" | head -c 120)"

body=$(curl -s http://127.0.0.1:8080/api/v1/shops/categories)
echo "$body" | grep -q '"code":0' && ok "GET /shops/categories code=0" || bad "分类接口异常"

code=$(curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8081/)
[ "$code" = "200" ] && ok "frontend 200" || bad "frontend 返回 $code"

echo "== 中间件 =="
docker exec tastelink-redis redis-cli ping 2>/dev/null | grep -q PONG && ok "Redis PONG" || bad "Redis 不通"
curl -s http://127.0.0.1:9200/_cluster/health | grep -q '"status"' && ok "ES 可访问" || bad "ES 不通"
$DC logs --tail=200 backend 2>/dev/null | grep -qiE "amqp|rabbit" && echo "  ⚠️  后端日志有 amqp 相关记录，确认 MQ 是否连通" || ok "后端日志无 MQ 异常关键字"

echo
[ "$FAIL" = "0" ] && echo "自检通过 ✅" || echo "存在失败项 ❌（见上）"
```
