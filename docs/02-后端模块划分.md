## 1. 后端技术栈

| 层 | 选型 | 说明 |

| ORM | MyBatis-Plus 3.5 | 分页插件、自动填充、条件构造器、逻辑外键靠字段维护 |

## 3. 功能模块与服务对照

| 业务模块 | Controller | Service 核心职责 |
|---|---|---|
| 用户/认证 | AuthController, UserController | 注册登录（BCrypt/JWT）、资料查询与编辑、当前登录人 |
| 店铺 | ShopController | 列表筛选排序、详情聚合、分类字典、店铺下点评列表 |
| 点评 | ReviewController | 发布点评（review+images+shop 计数同事务）、点评详情 |
| 互动 | InteractionController | 点赞/取消点赞幂等计数、评论增删 + 计数 |
| 关注 | FollowController | 关注/取关幂等计数、关注/粉丝列表（批量取用户摘要） |
| 首页 | RecommendService via HomeController | 热门店铺 + 热门点评，按城市筛选 |
| 文件 | FileController | 图片上传，抽象 `FileStorageService` 落地 OSS 或本地 |

## 4. 关键技术设计要点

### 4.1 统一返回体与全局异常
- `R<T> = {code, message, data}`，`code=0` 表示业务成功的统一约定见 `05-接口API设计.md`。
- `GlobalExceptionHandler`（`@RestControllerAdvice`）统一捕获：`MethodArgumentNotValidException`→400、`BusinessException`→业务码、`AccessDeniedException`/`AuthenticationException`→401/403、兜底 `Exception`→500；**不向前端泄露 SQL/堆栈**。
- 幂等冲突（如重复点赞）按业务成功处理，返回当前态，不抛错。

### 4.2 分页与自动填充
- `MybatisPlusConfig` 注册 `PaginationInnerInterceptor(DbType.MYSQL)`；分页统一用 `selectPage(page, wrapper)`，回填总数，再转 `PageResult`。
- `MetaObjectHandler` 自动填充 `createTime`(INSERT)、`updateTime`(INSERT_UPDATE)；实体加 `@TableField(fill=...)`。避免 `ON UPDATE` 全字段更新时被置空。

### 4.3 安全（JWT 链 + 白名单 + CORS）
- `SecurityConfig` 配 `SessionCreationPolicy.STATELESS`，禁用 CSRF，`addFilterBefore(JwtAuthFilter, UsernamePasswordAuthenticationFilter.class)`。
- **白名单**（`permitAll`）：注册/登录、`GET` 浏览类（shops/categories/reviews 详情与评论列表/users 主页与关注粉丝列表/home）。
- **顺序敏感**：`GET /users/me`（authenticated）必须配置在 `GET /users/**`（permitAll）之前。
- `JwtAuthFilter`：解析 `Authorization: Bearer` token，校验通过写 `SecurityContext`，失败不抛异常（交 `authenticationEntryPoint` 统一输出 401）。服务层用 `SecurityContextHelper.getCurrentUserId()` 取登录人。
- 密码 `BCryptPasswordEncoder`（strength=10）；任何 VO 不含 `password` 字段。
- CORS：`CorsConfigurationSource` 允许前端 dev/生产域名、常用方法与头、`allowCredentials=true`，经 `http.cors(withDefaults())` 启用。

### 4.4 文件存储抽象
- `FileStorageService` 接口（`service` 包）：核心方法 `upload(MultipartFile) -> {url, ossKey}`、`delete(ossKey)`。
- `OssFileStorageServiceImpl`：`@ConditionalOnProperty(prefix="storage", name="type", havingValue="oss")`，阿里云 OSS SDK，URL 由 `oss.domain + ossKey` 拼装。
- `LocalFileStorageServiceImpl`：`havingValue="local"` 且 `matchIfMissing=true`，存本地 `./data/uploads/yyyy/MM/uuid.ext`，`WebMvcConfig` 映射 `/static/uploads/**`，返回后端静态资源 URL。
- 业务层只依赖接口，不拼 URL；DB 存 `url`（可访问）+ `oss_key`（管理用）。

### 4.5 事务与幂等
- 冗余计数（点赞数/评论数/点评数/关注数/粉丝数/店铺评分汇总）在写入业务行的**同一 `@Transactional` 方法**内更新，失败整体回滚。
- 点赞：`INSERT` 撞唯一约束 `uk_review_user` 抛 `DuplicateKeyException` → 视为已点赞，返回当前计数，**不做「先查后写」**。
- 取消点赞/取关：`DELETE` 按 `affected rows` 判断，>0 才递减计数。
- 递减一律 `GREATEST(0, n-1)` 防止计数为负。
- 关注/取关复用 `uk_follower_followee` 唯一约束；不可关注自己在 Service 层校验。

### 4.6 逻辑外键与软删除
- 全部逻辑外键，不建物理 FK；关系靠 `shop_id`/`user_id`/`category_id`/`review_id` 等字段维护，Service 层校验引用存在性。
- 软删除统一用 `status`（1 正常 / 0 隐藏），不全局开启 MyBatis-Plus 逻辑删除插件；查询按需 `status=1` 过滤。

## 6. 代码规范约定

- 包名 `com.tastelink.<职责>`；实体与表一一对应，驼峰↔下划线自动映射。
- 请求 DTO 用 `@NotBlank/@Size/@Min/@Max` 等校验；Controller 形参加 `@Valid`。
- 响应统一封装为 `VO`，敏感字段（`password`）不出现。
- 时间字段返回统一 `yyyy-MM-dd HH:mm:ss`。
- 分页参数 `page`(从1起)/`size`，统一经分页插件，输出 `PageResult`。
- 接口实现严格遵循 `05-接口API设计.md` 的路径、参数与返回结构；契约变更需同步文档并升版本号。
