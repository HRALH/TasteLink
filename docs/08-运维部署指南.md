## 1. 总览

TasteLink = Spring Boot 后端(`:8080`) + Vite/React 前端(`:5173` 开发 / nginx `:8081` 部署) + MySQL 8 + (v2) Redis / RabbitMQ / Elasticsearch。

> v2 中间件三阶段均带**特性开关 + 降级回流**：中间件缺位时应用仍可启动，仅对应功能降级。MySQL 是唯一硬依赖（连接池急初始化）。

两种部署形态：

| 形态 | 场景 | 命令入口 |
|---|---|---|
| **A. 本地开发** | 改代码联调 | `docker compose up -d <mw>` 起中间件 + `mvn spring-boot:run` / `npm run dev` |
| **B. Docker 全栈** | 一键拉起完整栈，贴近生产 | `docker compose --project-directory . -f docker/docker-compose.yml up -d --build` |

端口速查：

| 服务 | 端口 | 说明 |
|---|---|---|
| 后端 API | 8080 | `/api/v1/**`、`/static/uploads/**` |
| 前端 dev | 5173 | Vite dev，`/api` 代理 → 8080 |
| 前端 nginx | 8081 | 生产静态 + `/api`、`/static/uploads` 反代后端 |
| MySQL | 3306 | |
| Redis | 6379 | |
| RabbitMQ | 5672 / 15672 | AMQP / 管理界面(guest/guest) |
| Elasticsearch | 9200 | |

## 3. 本地开发起栈

### 3.1 数据库初始化（手动，不会自动建表）

`spring.sql.init.mode=never`，需手动建库与导入：

```bash
mysql -uroot -p
```
```sql
CREATE DATABASE IF NOT EXISTS tastelink DEFAULT CHARACTER SET utf8mb4;
USE tastelink;
SOURCE backend/src/main/resources/db/schema.sql;   -- 建表（CREATE TABLE IF NOT EXISTS）
SOURCE backend/src/main/resources/db/data.sql;      -- 种子：店铺 / 分类 / 城市 / 角色种子
```

> `t_user.role`(v2 `USER` 默认 /`ADMIN`)、`t_shop.version`(v2 乐观锁) 列已在 schema 中；提权管理员见 `data.sql` 注释（注册后 `UPDATE t_user SET role='ADMIN'`）。

### 3.2 起中间件（按需）

仓库根 `docker-compose.yml` 仅含中间件（不含 MySQL，沿用本地实例）：

```bash
docker compose up -d redis rabbitmq elasticsearch   # 按需单个或全部
docker compose up -d xxl-job-admin                   # 调度中心（B5）；带 profile，需先建 xxl_job 库，见 §5.4
docker compose logs -f rabbitmq
docker compose down                                  # 停
```

> RabbitMQ 用标准 `rabbitmq:3-management`（TTL+DLX 免插件）；Elasticsearch 标准镜像**不带 IK 中文分词**（见 §5.3）；`xxl-job-admin` 默认不随 `up -d` 启动（`profiles: ["xxl-job"]`），且需宿主 MySQL 里先有 `xxl_job` 库（见 §5.4）。

### 3.3 后端配置 + 启动

`application.yml` 仅占位符。复制示例填真值：

```bash
cp backend/src/main/resources/application-local.yml.example backend/src/main/resources/application-local.yml
```

填入 `DB password`、`jwt.secret`(≥32 字符)；用 OSS 再填 AK/SK。`application-local.yml` 已 gitignore。

```bash
cd backend
mvn spring-boot:run          # :8080（默认 profile=local）
```

也可全程用环境变量覆盖（见 §6），无需 `application-local.yml`：

```bash
DB_PASSWORD=xxx JWT_SECRET=xxxx mvn spring-boot:run
```

### 3.4 前端启动

```bash
cd frontend
npm install
npm run dev      # :5173，Vite 把 /api 代理到 :8080，本地无 CORS
```

> 后端未起也能渲染骨架页；完整功能需后端在线。

## 4. Docker 全栈部署（`docker/`）

### 4.1 文件清单

| 文件 | 作用 |
|---|---|
| `docker/Dockerfile.backend` | 多阶段：`maven:3.9-eclipse-temurin-17` 构建 → `eclipse-temurin:17-jre` 运行，非 root |
| `docker/Dockerfile.frontend` | 多阶段：`node:20-alpine` 构建 → `nginx:1.27-alpine` 静态 + 反代 |
| `docker/nginx.conf` | SPA 回退 + `/api`、`/static/uploads` 反代后端 |
| `docker/docker-compose.yml` | 全栈编排：mysql + xxl-job-admin(profile) + redis + rabbitmq + elasticsearch + backend + frontend |
| `docker/xxl-job/tables_xxl_job.sql` | 调度中心建库脚本（官方 v2.4.1 原样收录），挂为 mysql 的 `03-` 初始化脚本 |
| `.env` | **不入库**（gitignore），由 §4.2 模板创建 |

### 4.2 `.env` 配置

`.env` 被 `.gitignore` 排除。从下方模板创建（必须至少填 `JWT_SECRET`/`DB_PASSWORD`）：

```bash
cat > .env <<'EOF'
# ===== MySQL =====
DB_NAME=tastelink
DB_PASSWORD=change-this-root-password      # 必改；含特殊字符时 compose 内已加引号保护

# ===== 后端 =====
SPRING_PROFILES_ACTIVE=local              # 配置全走环境变量，profile 维持 local
JWT_SECRET=replace-with-a-long-random-secret-at-least-32-chars   # 必改；JWT 签名密钥
STORAGE_TYPE=local                         # 或 oss
STORAGE_PUBLIC_BASE_URL=http://localhost:8080   # 浏览器可达后端地址（local 图片 URL 绝对拼接）
CORS_ORIGINS=http://localhost:5173,http://localhost:8081

# ===== v2 三阶段特性开关（任一 false 降级回 MySQL）=====
RANK_CACHE_ENABLED=true
RABBIT_ENABLED=true
SEARCH_ENABLED=true

# ===== OSS（STORAGE_TYPE=oss 时必填）=====
# OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
# OSS_AK=
# OSS_SK=
# OSS_BUCKET=
# OSS_DOMAIN=

# ===== COS（STORAGE_TYPE=cos 时必填；region 须与服务器同地域，迁移见 docs/14 §12）=====
# COS_REGION=ap-shanghai
# COS_SECRET_ID=
# COS_SECRET_KEY=
# COS_BUCKET=
# COS_DOMAIN=
EOF
```

> `.env.example` 因 gitignore 的 `.env.*` 规则会被忽略，故模板置于此文档而非独立文件。
>
> **`.env` 必须落在仓库根**（即执行 compose 命令的工作目录）。Compose 只从「工作目录 + 项目目录」读 `.env` 做 `${VAR}` 插值，放 `docker/.env` 不会被读到：`JWT_SECRET` 会因 `:?` 报错中断，而 `DB_PASSWORD` 会静默落回默认值 `rootpass`。

### 4.3 一键起 / 停

必须**在仓库根目录**且带 `--project-directory .`（使 build `context: .` 与挂载的 `./backend/...` 以仓库根解析；缺省 compose 会以 `docker/` 为项目目录，路径会错）：

```bash
# 首次构建并拉起全栈
docker compose --project-directory . -f docker/docker-compose.yml up -d --build

# 看后端启动日志
docker compose --project-directory . -f docker/docker-compose.yml logs -f backend

# 停
docker compose --project-directory . -f docker/docker-compose.yml down

# 清卷重置数据（重新执行 schema/data.sql，慎用：删 MySQL 与上传图片卷）
docker compose --project-directory . -f docker/docker-compose.yml down -v
```

起齐后：
- 前端 http://localhost:8081
- 后端 http://localhost:8080
- RabbitMQ 管理界面 http://localhost:15672（guest/guest）
- ES http://localhost:9200

### 4.4 构建说明

- **后端**：先 `COPY backend/pom.xml` 跑 `dependency:go-offline` 缓存依赖层，再 `COPY backend/src` 打 `clean package -DskipTests`，产出 fat jar 重命名为 `app.jar`；运行阶段 `eclipse-temurin:17-jre`，非 root 用户 `tastelink`。`JAVA_OPTS` 可运行时覆盖内存。
- **前端**：`npm ci`（无 lock 文件则 `npm install`）→ `VITE_API_BASE_URL=/api/v1` → `npm run build` 产 `dist/`，nginx 挂 `docker/nginx.conf`。

### 4.5 MySQL 自动初始化说明

`docker-compose.yml` 把 `schema.sql`/`data.sql` 挂到 `/docker-entrypoint-initdb.d/`，**仅在 `mysql_data` 卷为空时首次执行**（与 `spring.sql.init.mode=never` 契合）。改了 schema 想重灌 → `down -v` 再 `up -d`。

## 5. 中间件逐项配置与降级

沿用 `docs/06` 的「应用层完成、infra 待办」状态：

### 5.1 Redis（v2 Phase A 点评审热度排行）

- 配置键 `spring.data.redis.*`；env `REDIS_HOST`/`REDIS_PORT`/`REDIS_PASSWORD`/`REDIS_DB`。
- 排行逻辑：点赞后 `afterCommit` 写 ZSet `review:hot`，分数 `like*100 + min(reply,99)`；`ScheduledRankRebuild` 定时对账。
- **开关** `tastelink.rank.cache-enabled` ← env `RANK_CACHE_ENABLED`(默认 `true`)。置 `false` → 读写均回 MySQL，前端无感。
- env 配套：`RANK_REBUILD_CRON`(`0 */10 * * * *`)、`RANK_REBUILD_TOP_SIZE`(`200`)、`RANK_ZSET_KEY`(`review:hot`)。

### 5.2 RabbitMQ（v2 Phase C 店铺删除延时清理 / C-Full）

- 配置键 `spring.rabbitmq.*`；env `RABBITMQ_HOST`/`_PORT`/`_USER`/`_PASSWORD`/`_VHOST`、`RABBIT_RETRY_MAX_ATTEMPTS`。
- 删除流程：单事务标记 `shop.status=0` + 级联 `review.status=0` + 回扣计数 → `afterCommit` 发延时消息 → 消费端级联物理删（图→赞→评→店）→ `ScheduledShopCleanupReconcile` 对账兜底。延时用 **TTL+DLX 免插件**，标准镜像即可。
- **开关** `tastelink.rabbitmq.enabled` ← env `RABBIT_ENABLED`(默认 `true`)。置 `false` → 不发消息，对账调度直接物理清理（无延时窗口，删店仍生效）。
- env 配套：`RABBIT_CLEANUP_DELAY_MS`(`5000`)、`RABBIT_CLEANUP_RECON_CRON`(`0 */2 * * * *`)、`RABBIT_CLEANUP_RECON_GRACE_MS`(`30000`)。

### 5.3 Elasticsearch（v2 Phase D 店铺关键词检索）

- 配置键 `spring.elasticsearch.*`；env `ES_URIS`(默认 `http://localhost:9200`)。
- `ShopController.listShops` 的 `keyword` 走 ES（`name` MUST + `status/category/city` 过滤 + 回查 MySQL 补 VO）；异常/禁用 → 返回 `null` → controller 降级回 MySQL `LIKE`。
- **开关** `tastelink.search.enabled` ← env `SEARCH_ENABLED`(默认 `true`)。置 `false` → keyword 直回 `LIKE`。env 配套：`SEARCH_REBUILD_CRON`(`0 */10 * * * *`)。
- **infra 待办 A（IK 中文分词）**：标准 ES 镜像无 IK，CJK 命中≈`LIKE` 直到装 `analysis-ik` 并以 `ik_max_word`/`ik_smart` 重建索引：
  ```bash
  docker exec -it tastelink-elasticsearch \
    bin/elasticsearch-plugin install analysis-ik
  docker compose restart elasticsearch
  ```
  再触发全量重建（等 `SEARCH_REBUILD_CRON`，或重启后端由 `ShopIndexInitializer`/`ScheduledShopReconcile` 兜底）。补 IK 不动应用代码，需 reindex。
- **infra 待办 B（Canal binlog 增量同步）**：未部署 canal-server/canal-adapter、未开 binlog。当前以 `ScheduledShopReconcile` 定时全量重建为唯一同步源（最终一致、非实时）。落地 Canal 为独立进程，不在应用内，见 `docs/06` §6.3 D7。

### 5.4 XXL-JOB（B5 定时任务调度中心）

把三个对账/重建任务（Phase A/C/D 的 `@Scheduled`）的**触发权**交给调度中心，换来可视化调度、执行日志、失败告警与多实例路由。

- 配置键 `tastelink.xxl-job.*`；env `XXL_JOB_ENABLED`、`XXL_JOB_ADMIN_ADDRESSES`、`XXL_JOB_ACCESS_TOKEN`、`XXL_JOB_EXECUTOR_APPNAME`/`_ADDRESS`/`_IP`/`_PORT`/`_LOG_PATH`/`_LOG_RETENTION_DAYS`。
- **开关** `tastelink.xxl-job.enabled` ← env `XXL_JOB_ENABLED`（**默认 `false`**）。false 时：不创建执行器 bean、不绑 9999 端口、不连 admin，三个任务仍由本地 `@Scheduled` + ShedLock 驱动——**与未接入前完全一致**。两个 compose 文件的 `xxl-job-admin` 服务都带 `profiles: ["xxl-job"]`，默认 `up -d` 不会起它，故老部署升级后不受影响。
- **⚠️ 开启前必须确认 admin 就绪**：`enabled=true` 时本地 cron 已被让位，若 admin 不可达（库没建、服务没起、令牌不符），三个对账任务会**静默停摆**——admin 侧看不到、应用侧只有 executor 注册失败的 warn 日志。这是本开关唯一的高风险点。
- 启用三步：
  ```bash
  # ① 建 xxl_job 库（新数据卷由 03-xxl-job.sql 自动建；老数据卷需手动导入）
  docker compose --project-directory . -f docker/docker-compose.yml \
    exec -T mysql mysql -uroot -p"$DB_PASSWORD" < docker/xxl-job/tables_xxl_job.sql
  # ② 起 admin（8888）并登录 http://localhost:8888/xxl-job-admin
  docker compose --project-directory . -f docker/docker-compose.yml --profile xxl-job up -d
  # ③ 置 XXL_JOB_ENABLED=true 后重建 backend 容器
  ```
  登录默认 `admin` / `123456`（**立即改密**）；在「执行器管理」新增 `AppName=tastelink-executor`（`XXL_JOB_EXECUTOR_APPNAME` 需一致，不一致则不派发）。
- **任务配置（handler 名必须逐字一致，否则任务静默不触发）**：在「任务管理」建下表三个任务：

| JobHandler | 作用 | 建议 cron（等同原 Spring cron，可直接照搬） | 原配置键 |
|---|---|---|---|
| `rankRebuildHandler` | 重建热度排行 ZSet | `0 */10 * * * *` | `RANK_REBUILD_CRON` |
| `shopCleanupReconcileHandler` | 补清删店滞留数据 | `0 */2 * * * *` | `RABBIT_CLEANUP_RECON_CRON` |
| `shopIndexReconcileHandler` | ES 店铺索引全量重建 | `0 */10 * * * *` | `SEARCH_REBUILD_CRON` |

  路由策略用默认 `FIRST`（只挑一台执行）即得多实例去重；`@Scheduled` 侧仍保留 `@SchedulerLock`，供关闭开关时的降级路径使用。
  **别给 `@XxlJob` handler 补 `@SchedulerLock`**：`enabled=true` 时本地 `@Scheduled` 只是空转返回，但它仍按原 cron 抢同名锁（`lockAtLeastFor` 5~10 秒），handler 若也用同名锁，admin 触发的这一轮就可能落在窗口里被**静默跳过**。详见 `XxlJobConfig` 类注释。
- **执行器端口**：admin 通过 executor 的 `9999` 端口**回调派发**任务。同 compose 网络内按容器 IP 自动注册即可；若自动推导的 IP 不通（容器多网卡、跨宿主机），显式指定 `XXL_JOB_EXECUTOR_ADDRESS=http://backend:9999/`。
- **执行结果语义**：任务内部沿用「吞异常 + 下一周期重试」的既有可靠模型，故 admin 侧通常显示成功；失败详情看应用日志 `warn`。`shopIndexReconcileHandler` 会把灌入文档数写进执行日志，`XXL_JOB_ENABLED=false` 或 `SEARCH_ENABLED=false` 时该 handler 直接返回 0 不触碰 ES。
- 内存：admin 自身约 300~500MB（Spring Boot + 内嵌 Tomcat）——`docs/14` 的 4C8G 内存账需把它算进去。

### 5.5 延后变体（当前不做）

`Redisson`（替乐观锁）——主序列未触发多实例高并发，见 `docs/06` §7。原列于此的 `XXL-JOB` 已落地（见 §5.4）。

## 7. 文件存储

三种模式由 `storage.type` 选择，三者都只实现 `FileStorageService` 接口，**业务代码永不拼 URL**：

| 模式 | 写入 | 对外访问 | 注意 |
|---|---|---|---|
| `local`(默认) | `STORAGE_LOCAL_PATH/yyyy/MM/uuid.ext` | 后端 `/static/uploads/**` | 库内存的是**绝对 URL**（`STORAGE_PUBLIC_BASE_URL + /static/uploads/…`），生产务必把 `STORAGE_PUBLIC_BASE_URL` 设为浏览器可达后端地址。图片与服务器同生共死，切域名必须改库（见 `docs/14 §8.3`） |
| `oss` | 阿里云 OSS 对象 `uploads/yyyy/MM/uuid.ext` | `OSS_DOMAIN` 或 `https://{bucket}.{endpoint}` | 跨厂商（服务器在腾讯云时上传仍走公网、占服务器带宽） |
| `cos` | 腾讯云 COS 对象 `uploads/yyyy/MM/uuid.ext` | `COS_DOMAIN` 或 `https://{bucket}.cos.{region}.myqcloud.com` | 与 `oss` **同构**（同一 key 形态、同一 URL 反推规则），迁移与清理逻辑通用。桶与服务器**同地域**时默认域名自动解析到内网、流量免费，**无需任何端点配置** |

共用行为：

- `upload` 前一律过 `UploadUtil.validateImage`：扩展名白名单（jpg/jpeg/png/webp/gif）+ **文件头魔数嗅探**（防改名 webshell）——local 模式下文件经 `/static/uploads/**` 直出，属存储型 XSS 面；
- `oss_key` 列自 B1-1 起真实入库（写点评时由 `ossKeyFromUrl(url)` 反推得到），不再恒为空；历史空串行仍靠 `url` 反查兜底；
- 删店物理清理取 `oss_key`，为空则回退 `ossKeyFromUrl(url)`；**删除失败不阻断主流程**（记 warn，由对账调度重清）；
- `isOwnedUrl(url)` = 前缀命中本实现签发形态 + key 形态安全（无 `..`、非绝对路径），用于点评图片入库前的外链/穿越防御；
- `POST /api/v1/files/image` **调用即落盘**：用户选了图但没走完表单提交，存储上就会留下**无 DB 引用的孤儿文件**（不会自动清理；`local → COS` 迁移用 `coscmd upload -r` 整目录推时会把它们一起搬过去）。判断某对象是否还被引用，看库里有没有对应的 `url`。

> local → COS/OSS 的切换与历史数据迁移步骤见 `docs/14 §12`。

## 9. 生产部署清单

- [ ] **凭据经环境变量注入，不入镜像/不入库**：`JWT_SECRET`、`DB_PASSWORD`、`OSS_AK/SK`。`.env`/`application-local.yml`/`*.key` 均 gitignore，提交前扫敏感（记忆 `no-sensitive-in-git`）。
- [ ] **JWT_SECRET** ≥32 字符，随机，跨实例共享。
- [ ] **DB** 用独立实例（非容器默认 rootpass）；Hikari 池 `maximum-pool-size` 按负载调。
- [ ] **`STORAGE_PUBLIC_BASE_URL`** 设为外网可达后端地址（或经入口 nginx 同源反代 `/static/uploads`，则可指向前端域名）。
- [ ] **CORS_ORIGINS** 列出前端真实域名；若全走入口 nginx 同源反代 `/api`，理论上不触发 CORS（仍建议配置兜底）。
- [ ] **反向代理**：建议入口 nginx 暴露单域名，`/api` `/static/uploads` 反代后端，根 `/` 走前端静态；client_max_body_size ≥20m。
- [ ] **中间件**：Redis 建议带密码（`redis-server --requirepass` + `REDIS_PASSWORD`）；RabbitMQ 改强密码 + 限制管理界面；ES 在公网务必开 xpack 安全。
- [ ] **日志/时区**：`TZ=Asia/Shanghai`（Dockerfile 已设）；时区 `application.yml` Jackson `Asia/Shanghai`。
- [ ] **健康检查**：后端无 actuator，可对 `:8080` TCP 探活或加 actuator 依需引入。
- [ ] **重启策略**：容器 `restart: unless-stopped`；MySQL 卷定期备份。
- [ ] **infra 待办协调**：上 Phase D 实时搜索前先装 IK + 部署 Canal + 开 binlog + reindex（见 §5.3）。

## 10. 常见问题排羁

| 现象 | 原因 / 处置 |
|---|---|
| 后端启动失败：`Communications link failure` | MySQL 未起或不可达。本地先 `mysql -uroot -p` 确认；Docker 确认 `mysql` 健康、`DB_HOST=mysql`、`DB_PASSWORD` 与 `MYSQL_ROOT_PASSWORD` 一致。 |
| 应用启动正常，但 Redis/RabbitMQ 未起不报错 | 设计如此：三阶段中间件均懒加载/可降级，不影响启动。 |
| 首页热门点评退化 MySQL 排序 | Redis 不可用或 `RANK_CACHE_ENABLED=false`；`ScheduledRankRebuild` 会兜底。起 Redis 即恢复。 |
| 删店后关联评论延迟才物理清空 | 正常：`RABBIT_CLEANUP_DELAY_MS`(默认 5s) 延时窗口。MQ 不可达时由 `RABBIT_CLEANUP_RECON_CRON` 对账直接清。 |
| keyword 中文命中≈LIKE | ES 未装 IK（infra 待办 A），按 §5.3 装 `analysis-ik` 并重建索引。 |
| ES 结果陈旧 | Canal 未到位（infra 待办 B），仅靠 `SEARCH_REBUILD_CRON` 定时全量重建；改店后等下次 cron 或重启后端。 |
| 图片显示 404 | `STORAGE_PUBLIC_BASE_URL` 与浏览器地址不匹配（local 存的绝对 URL）。设为前端可达入口或后端外网地址。 |
| Docker 起栈路径找不到 `backend/pom.xml` | 未带 `--project-directory .`，参考 §4.3 固定命令。 |
| 改了 schema.sql 不生效 | `mysql_data` 卷已存在 → 不重跑 init。`down -v` 清卷后再 `up -d`。 |
| 构建后端镜像 `*.jar` 找不到 | `target/` 无产物 = `mvn package` 失败，看构建日志（多半是测试编译错误或依赖拉取失败）；构建已 `-DskipTests`。 |
| 端口冲突 8080/5173/3306… | 本地已有占用；改 compose `ports` 映射或停本地实例。 |
