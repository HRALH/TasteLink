# TasteLink 从零启动指南(clone 到跑通)

| 项 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 更新日期 | 2026-09-16 |
| 适用对象 | 拿到仓库、想本地跑通全部功能(含数据库)的外部同学 |
| 关联文档 | `08-运维部署指南.md`(全栈 Docker / 中间件细节)、`05-接口API设计.md`、`04-数据库表设计.md` |

> 本文目标:**clone → 跑通 → 看见首页种子点评 → 注册登录 → 发点评/点赞 → 收到通知**,全程不绕路。两条路线:
> - **路线 A:本地原生起栈**(改代码联调,推荐先走这条,理解每一步)。§1~§7。
> - **路线 B:Docker 一键全栈**(贴近生产,MySQL + 中间件 + 前后端全拉起)。§8。
>
> MySQL 是**唯一硬依赖**(连接池急初始化);Redis / RabbitMQ / Elasticsearch 三个中间件**不起也能跑**,对应功能自动降级回 MySQL。本文 §5 把「要不要起中间件」讲清楚,你可以先跳过。

## 0. 你需要先装什么

| 组件 | 版本 | 自查命令 | 说明 |
|---|---|---|---|
| JDK | **17+** | `java -version` | 后端运行;**JDK 8 会在 `--release` 报错**(见 §13 排错) |
| Maven | 系统 `mvn`(无 wrapper) | `mvn -v` | 仓库没带 `mvnw`,需本机装 |
| Node | **20+** | `node -v` | 前端 |
| MySQL | **8.x** | `mysql --version` | utf8mb4 / InnoDB |
| Docker + compose | v2(可选) | `docker compose version` | 只在跑 §5 中间件或 §8 全栈时需要 |

> macOS 用 Homebrew:`brew install openjdk@17 maven node mysql docker`(MySQL 也可直接装官方 Docker 镜像,见 §2 选项二)。本机若有多版本 JDK,跑 Maven 时强制指 17:`JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn ...`。

## 2. 准备数据库(不会自动建表)

后端 `spring.sql.init.mode=never`,**不会自动建库 / 建表**,必须手动导入。两种方式任选:

### 选项一:本机已装 MySQL

```bash
mysql -uroot -p
```

```sql
CREATE DATABASE IF NOT EXISTS tastelink DEFAULT CHARACTER SET utf8mb4;
USE tastelink;
SOURCE backend/src/main/resources/db/schema.sql;     -- 建 10 张表(CREATE TABLE IF NOT EXISTS)
SOURCE backend/src/main/resources/db/data.sql;        -- 种子:4 家店 / 8 分类 / 3 个不可登录种子作者 + 14 条点评 + 点赞 / 评论 + 计数对齐
```

### 选项二:用 Docker 起一个临时 MySQL

> 注意:仓库根的 `docker-compose.yml` **刻意不含 MySQL**(避免与本地 3306 冲突),这里我们手动起一个独立的。

```bash
docker run -d --name tastelink-mysql \
  -e MYSQL_ROOT_PASSWORD=rootpass \
  -p 3306:3306 \
  mysql:8

# 等它 healthy(约 20~40s)
docker exec -i tastelink-mysql mysql -uroot -prootpass \
  -e "CREATE DATABASE IF NOT EXISTS tastelink DEFAULT CHARACTER SET utf8mb4;"

docker exec -i tastelink-mysql mysql -uroot -prootpass tastelink \
  < backend/src/main/resources/db/schema.sql
docker exec -i tastelink-mysql mysql -uroot -prootpass tastelink \
  < backend/src/main/resources/db/data.sql
```

### 种子账号说明(重要)

- 种子里有 `admin` + `seed_wang` / `seed_coffee` / `seed_may` 等账号,但它们的密码都是**占位 BCrypt 哈希 `$2a$10$placeholder_bcrypt_hash_replace_me`,不可登录**(这是刻意的,不向仓库固化任何可用口令)。
- 种子用户与点评只是为了让**首页不空**,游客一进来就能看见 14 条点评(上海/北京/杭州 4 家店)。
- 你要登录体验,需**自己注册一个账号**(§7)。提权管理员见 §9。

## 3. 配置后端真实凭据

`backend/src/main/resources/application.yml` **只有占位符**(env-var 引用,无真值)。复制示例填真值:

```bash
cp backend/src/main/resources/application-local.yml.example \
   backend/src/main/resources/application-local.yml
```

打开 `application-local.yml`,至少改两处(其余按需):

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/tastelink?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: 你的真实数据库密码      # ← 改这里(选项二 Docker 起的就是 rootpass)
  data:
    redis:
      host: localhost
      port: 6379
      password:                         # 6379 无密码留空
  rabbitmq:
    host: localhost
    port: 5672
    username: guest
    password: guest
    virtual-host: /
  elasticsearch:
    uris: http://localhost:9200

tastelink:
  jwt:
    secret: 换成至少32字符的随机字符串    # ← 改这里
  storage:
    type: local                          # 默认本地存储;用 OSS 再展开下面 oss 块
  rank:
    cache-enabled: true                   # 没 Redis 见 §5
  rabbitmq:
    enabled: true                         # 没 RabbitMQ 见 §5
  search:
    enabled: true                        # 没 ES 见 §5
```

`application-local.yml` 已被 `.gitignore` 排除,**不会提交**,放心填。

> 不想建本地配置文件也行,直接用环境变量覆盖(等价):

```bash
export DB_PASSWORD=你的真实数据库密码
export JWT_SECRET=随机至少32字符
cd backend && mvn spring-boot:run
```

## 5. (可选)起中间件 —— 不起也能跑

三个中间件都是**懒加载 + 特性开关**,不起时对应功能降级回 MySQL,**应用照常启动**,只是部分体验打折:

| 中间件 | 提升的功能 | 不起时的降级 | 起法 |
|---|---|---|---|
| Redis | 首页热门点评走 ZSet 排序 | 回 MySQL 排序(慢一点,功能不变) | `docker compose up -d redis` |
| RabbitMQ | 删店 5s 延时清理窗口 | 对账调度直接近实时清理(删店仍生效) | `docker compose up -d rabbitmq` |
| Elasticsearch | 店铺 keyword 中文/模糊检索 | keyword 回 MySQL `LIKE`(中文连续命中弱) | `docker compose up -d elasticsearch` |

> 命令里的 `docker compose up -d <服务名>` 指向**仓库根的 `docker-compose.yml`**(只有中间件三件套,无 MySQL),**须在仓库根目录执行**。

**第一次跑通,可以完全不起中间件**(三个开关会在连通失败时自动降级,日志里可能有 warn 但不炸)。想体验完整效果再补:

```bash
docker compose up -d redis rabbitmq elasticsearch
docker compose logs -f redis          # 看日志确认起来
```

不想降级、想明确关掉某项:在 `application-local.yml` 设 `rank.cache-enabled: false` / `rabbitmq.enabled: false` / `search.enabled: false`(或对应环境变量 `RANK_CACHE_ENABLED=false` 等)。

## 7. 验证:从首页到收通知跑一遍

1. **首页**:访问 `http://localhost:5173`,应**看见 14 条种子点评 + 4 家店**(上海/北京/杭州),评分不是 `0.0`(F5 已修"暂无评分"空态)。
2. **注册**:点右上「注册」,用户名 + 密码(≥8 且含字母+数字),如 `alice / Alice12345`。
3. **登录**:用刚注册的号登入,顶栏出现头像 + 铃铛。
4. **发点评**:进任意店铺详情 → 「写点评」→ 先「上传图片」拿 URL → 填文字 + 1~5 分 → 提交,店铺评分/点评数应实时 +1。
5. **收通知(用第二个号验证)**:再注册 `bob / Bob12345` 并登录 → bob 进任意 alice 的点评点「赞」→ **回到 alice 账号**(或两个浏览器)→ 顶栏铃铛在 **≤30s 内**出现红点 → 点开通知列表 → 看见「bob 赞了你的点评」→ 标记已读红点消失。
6. **关注 feed**:alice 关注 bob → 顶栏「关注」入口 → 进 `/following` → 看见 bob 的点评流。
7. **举报**:登录态在某条非自己发的点评上看见「举报」入口 → 选理由提交 → 重复举报会提示「已举报过该内容」。

走到这里,核心闭环通。

## 8. 路线 B:Docker 一键全栈(可选,贴近生产)

适合不想本地装 MySQL/JDK/Node,直接全拉起来。`docker/docker-compose.yml` 编排:MySQL + Redis + RabbitMQ + Elasticsearch + backend + frontend。

### 8.1 创建 `docker/.env`(必填)

`docker/.env` 被 `.gitignore` 排除。至少填 `JWT_SECRET` 与 `DB_PASSWORD`:

```bash
cat > docker/.env <<'EOF'
# ===== MySQL =====
DB_NAME=tastelink
DB_PASSWORD=change-this-root-password

# ===== 后端 =====
SPRING_PROFILES_ACTIVE=local
JWT_SECRET=replace-with-a-long-random-secret-at-least-32-chars
STORAGE_TYPE=local
STORAGE_PUBLIC_BASE_URL=http://localhost:8080
CORS_ORIGINS=http://localhost:5173,http://localhost:8081

# ===== v2 三阶段特性开关(任一 false 降级回 MySQL)=====
RANK_CACHE_ENABLED=true
RABBIT_ENABLED=true
SEARCH_ENABLED=true

# ===== OSS(STORAGE_TYPE=oss 时必填)=====
# OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
# OSS_AK=
# OSS_SK=
# OSS_BUCKET=
# OSS_DOMAIN=
EOF
```

### 8.2 一键拉起

⚠️ **必须在仓库根目录**且带 `--project-directory .`,否则 build context 与挂载路径会解析错:

```bash
# 首次构建并拉起全栈
docker compose --project-directory . -f docker/docker-compose.yml up -d --build

# 看后端启动日志(等到 Started ...)
docker compose --project-directory . -f docker/docker-compose.yml logs -f backend

# 停
docker compose --project-directory . -f docker/docker-compose.yml down

# 清卷重置数据(重新执行 schema/data.sql,慎用:删 MySQL 与上传图片卷)
docker compose --project-directory . -f docker/docker-compose.yml down -v
```

起齐后:

- 前端 **http://localhost:8081**
- 后端 http://localhost:8080
- RabbitMQ 管理界面 http://localhost:15672(guest/guest)
- ES http://localhost:9200

### 8.3 数据库自动初始化说明

`docker-compose.yml` 把 `schema.sql`/`data.sql` 挂到 MySQL 镜像的 `/docker-entrypoint-initdb.d/`,**仅在 `mysql_data` 卷为空(首次)时执行**。**改了 schema.sql 想重灌**:`down -v` 清卷再 `up -d`。

## 9. 提权一个管理员(体验后台)

后台接口 (`/api/v1/admin/**`) 需 `ADMIN` 角色,种子 `admin` 账号是占位哈希不可登录。提权真实管理员:

```bash
# 1) 先在前端注册一个普通账号(如 alice)
# 2) 在 MySQL 里把它提为 ADMIN:
mysql -uroot -p tastelink -e "UPDATE t_user SET role='ADMIN' WHERE username='alice';"
# 或 Docker MySQL:
docker exec -i tastelink-mysql mysql -uroot -prootpass tastelink \
  -e "UPDATE t_user SET role='ADMIN' WHERE username='alice';"
```

> 注意:前端页面缓存了登录时的 token,**提权后需要重新登录**(让新 role 进 JWT claim),顶栏才会出现「店铺管理 / 内容治理」入口。真正鉴权在服务端,前端 UI 只是把 role 解出来做提示。

提权后体验:
- `/admin/shops`:编辑店铺(并发改同店会 409「请刷新重试」——乐观锁);删除店铺(5s 延时清理,合并期间刷新)。
- `/admin/reviews`:内容治理 —— 下架/恢复点评(店铺评分/点评数会镜像回扣)、查举报记录。

## 13. 常见问题排错

| 现象 | 原因 / 处置 |
|---|---|
| 后端编译报 `Fatal error compiling: 无效的标记: --release` | `JAVA_HOME` 指向了 JDK 8。强制用 17:`JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn spring-boot:run`(或全局 `export JAVA_HOME=...`) |
| 后端启动报 `Communications link failure` | MySQL 未起 / 不可达。确认进程在、端口 3306 没占、`application-local.yml` 的 `url/username/password` 与 §2 一致。 |
| 后端起得来,但 `/home` 报数据库错 | 忘了跑 `schema.sql` / `data.sql`,或 SOURCE 的是空库。重跑 §2。 |
| 首页热门点评走 MySQL(没走缓存) | 正常:Redis 没起或 `RANK_CACHE_ENABLED=false`;起 Redis 或保持默认即可,功能不缺。 |
| 店铺关键词中文搜不太准 | 正常:ES 未装 IK 中文分词(infra 待办)。中文连续命中约等于 `LIKE`。装 `analysis-ik` + reindex 才提升,见 `docs/08 §5.3`。改动只影响 infra,不动应用代码。 |
| 删店后评论等几秒才清空 | 正常:`RABBIT_CLEANUP_DELAY_MS` 默认 5s 延时窗口(便于撤销误删)。MQ 不可达时由对账调度近实时清。 |
| 上传图片在浏览器显示 404 | `STORAGE_PUBLIC_BASE_URL` 与浏览器地址不匹配(local 模式存的是绝对 URL)。设为前端可达入口或后端外网地址,默认 `http://localhost:8080` 适合本地原生。 |
| 图片上传 401 | 上传接口需登录。确认前端已登录、token 注入了 `Authorization` 头。 |
| CORS 报错 | 本地 dev 用 Vite 代理,理论上不触发 CORS。若分离部署,确认 `CORS_ORIGINS` 含你的前端域名。 |
| 改了 `schema.sql` 再启动不生效 | DB 卷已有数据,init 不重跑。本地原生:重跑 `SOURCE schema.sql`(IF NOT EXISTS 不会改既有表,需先 DROP 或换库);Docker:`down -v` 清卷再 `up -d`。 |
| 提权 ADMIN 后前端没出「管理」入口 | role 在登录时写入 JWT,提权后需**重新登录**让新 role 进 token;前端 role 仅供 UI 提示,真鉴权在后端。 |
| Docker 起栈报找不到 `backend/pom.xml` | 没带 `--project-directory .`。固定用 §8.2 的完整命令,且在仓库根执行。 |
| `mvn test` 报找不到测试 / 跳过集成测试 | 集成测试默认 skip,要 `-DRUN_IT=true` 且本机有 Docker 才跑;单测无需。 |
| 端口被占用(8080/5173/3306…) | 本地已有占用。停本地实例,或改 compose 映射 / Vite 的 `--port`。 |
