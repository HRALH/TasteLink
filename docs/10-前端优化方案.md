## F2 — 数据获取层(最大面积技术债) ✅ 653cd53(1/3 Provider+浏览页) + 70082e1(2/3 用户页) + 14e830e(3/3 互动/后台页,lint warning 清零)

**现状**:9 处手写 `useEffect+useState` 复制同一模式(`HomePage.tsx:20-27`、`ShopListPage.tsx:24-45`、`ShopDetailPage.tsx:42-60`、`UserHomePage.tsx:41-59`、`MePage.tsx:25-36`、`ReviewDetailPage.tsx:48-67`、`FollowList.tsx:22-30`、admin 两页),带来三类实际问题:

1. **竞态**:切筛选/翻页时旧响应覆盖新数据(effect 无 abort/序号戳);
2. **错误吞没**:`.catch(() => {})` 让接口挂掉呈现「暂无内容」,用户无法区分网络错误与真无数据;
3. **重复拉取**:分类字典在 3 处各自请求且无缓存。

**方案**:引入 `@tanstack/react-query`——一次解决竞态(自动)、缓存(字典 `staleTime: Infinity`)、错误态、loading 态;9 处逐页迁移。
轻量替代(若不想引依赖):自写 `useFetch` hook 带 AbortController + 请求序号戳 + 统一错误态。**推荐 React Query**,后续乐观更新(F6 测试目标)也能用其 mutation 模式收敛。
**验证**:迁移后 oxlint 的 11 条 `react(set-state-in-effect)` warning 应清零;每页保留「加载中/错误重试/空态」三态。
