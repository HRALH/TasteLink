## 1. 项目背景与目标

TasteLink 是一个面向城市餐饮推荐与社交互动的平台。用户可以搜索和浏览餐饮店铺、发布点评、点赞评论、关注其他用户，并基于用户内容贡献形成餐饮口碑社区。

**MVP 目标**：以最小代价验证「店铺浏览 + 点评 UGC + 社交互动」的核心闭环跑通，形成基础的餐饮口碑社区。

**不追求**：复杂推荐算法、实时 feed 流、商业变现与运营后台。这些在后续版本演进。

## 2. 名词定义与角色

### 2.1 名词定义

| 名词 | 说明 |
|---|---|
| 店铺（Shop） | 餐饮店铺，平台的基础内容主体，由系统/运营维护，MVP 不开放用户创建 |
| 点评（Review） | 用户针对某店铺发布的图文评价，包含文字、评分、图片 |
| 评论（Comment） | 其他用户对某条点评的文字回复，MVP 仅单层（不含嵌套） |
| 主分类（Category） | 店铺菜系分类，如火锅、咖啡、烧烤、日料等，一店一主分类 |
| 热门（Hot） | 基于计数排序的展示口径，店铺热度≈点评数，点评热度≈点赞数 |

### 2.2 角色

| 角色 | 说明 | 权限边界 |
|---|---|---|
| 游客 | 未登录访问者 | 可浏览店铺、点评、首页、用户主页与关注/粉丝列表，不可发布、互动、关注 |
| 登录用户 | 已注册并登录的用户（`t_user.role=USER`，默认） | 在游客权限基础上，可发布点评、点赞/评论、关注用户、维护个人资料 |
| 管理员 | 角色 `t_user.role=ADMIN`（v2 Phase B 转正） | 在登录用户基础上，可经 `/api/v1/admin/**` 编辑店铺；并发改同店走乐观锁，后提交者获 409 而非覆盖 |

> MVP 仅设普通用户角色；管理员角色自 v2 Phase B 起接入（仅店铺写与连锁理，对应 `docs/06` Phase B），商家入驻仍后置。

## 3. 功能需求

下文每个功能项标注**优先级**：P0（MVP 必须）、P1（MVP 范围内的小增强）、×（MVP 不做）。

### 3.1 用户模块

| 功能 | 优先级 | 说明 | 规则/约束 |
|---|---|---|---|
| 用户注册 | P0 | 账号密码注册 | `username` 唯一；密码长度≥8 且含字母+数字；密码 BCrypt 加密存储 |
| 用户登录 | P0 | 账号密码登录，签发 JWT | 登录返回 token、用户基本信息；token 无状态，默认有效期 24h |
| 用户信息展示 | P0 | 查看任意用户主页资料 | 公开访问；展示昵称、头像、简介、关注数、粉丝数、点评数；不在任何响应中回传密码 |
| 修改头像、昵称、简介 | P0 | 编辑本人资料 | 仅可修改本人；头像通过图片上传接口获得 URL 后提交 |

> 用户名（`username`）注册后 MVP 阶段不可修改，作为登录唯一标识；昵称（`nickname`）可改。

### 3.2 店铺模块

| 功能 | 优先级 | 说明 | 规则/约束 |
|---|---|---|---|
| 店铺列表 | P0 | 分页展示店铺 | 支持按关键词、分类、城市筛选；支持按热度排序 |
| 店铺搜索 | P0 | 关键词搜索店铺 | MVP 按 `name LIKE %keyword%` 实现全文搜索，不上 ES |
| 店铺详情 | P0 | 单店铺详情页 | 展示店铺基础信息 + 平均评分 + 点评数 + 近期点评预览 |
| 店铺分类 | P0 | 分类筛选与分类字典 | 火锅/咖啡/烧烤/日料等；分类为字典表，一店一主分类 |

> 店铺数据由系统/运营导入维护，MVP **不开放**用户创建/编辑店铺的前端入口。

### 3.3 点评模块

| 功能 | 优先级 | 说明 | 规则/约束 |
|---|---|---|---|
| 发布点评 | P0 | 对某店铺发布点评 | 含文字、评分（1~5 整数）、0~9 张图片；图片先经上传接口获得 URL |
| 查看店铺下点评列表 | P0 | 店铺详情下的点评流 | 分页；支持按时间倒序或点赞数倒序排序 |

> 点评关联一个店铺与一个发布用户。点评创建时同步维护店铺的点评数与平均评分。

### 3.4 互动模块

| 功能 | 优先级 | 说明 | 规则/约束 |
|---|---|---|---|
| 点赞点评 | P0 | 对某点评点赞 | 幂等：重复点赞不报错、计数不变 |
| 评论点评 | P0 | 对某点评发表评论 | 单层文字评论，MVP 不支持嵌套/楼中楼 |
| 取消点赞 | P0 | 撤销对某点评的点赞 | 幂等：未点过赞也返回成功、计数不变 |

> MVP 仅点评可被点赞，评论不可被点赞。

### 3.5 关注模块

| 功能 | 优先级 | 说明 | 规则/约束 |
|---|---|---|---|
| 关注用户 | P0 | 关注其他用户 | 幂等：重复关注不报错；关注数/粉丝数同事务维护 |
| 取消关注 | P0 | 取消关注某用户 | 幂等：未关注也返回成功 |
| 关注列表 | P0 | 查看某人关注了谁 | 公开访问；分页 |
| 粉丝列表 | P0 | 查看某人的粉丝 | 公开访问；分页 |

> 不可关注自己（前端/后端校验）。

### 3.6 首页推荐

| 功能 | 优先级 | 说明 | 规则/约束 |
|---|---|---|---|
| 热门店铺 | P0 | 首页展示热门店铺 | 按点评数（+点赞数）倒序取若干条 |
| 热门点评 | P0 | 首页展示热门点评 | 按点赞数（+评论数）倒序取若干条 |
| 按城市筛选 | P0 | 首页支持按城市筛选热门内容 | 店铺带城市字段；点评冗余城市字段以避免 JOIN |

## 4. 业务规则与约束

| 编号 | 规则 |
|---|---|
| R1 | 评分取 1~5 的整数，由后端校验（`@Min(1) @Max(5)`） |
| R2 | 单条点评图片数量上限 9 张，顺序保留 |
| R3 | 评论为单层结构，无 `parent_id`，不支持楼中楼与回复引用 |
| R4 | 点赞/关注/取消点赞/取消关注均需幂等，靠数据库唯一约束与受影响行数保证，不依赖「先查后写」 |
| R5 | 计数类字段（点赞数、评论数、点评数、关注数、粉丝数、店铺点评数、店铺平均评分）为冗余字段，在业务写入时同事务维护 |
| R6 | 不可关注自己 |
| R7 | 用户名注册后不可修改；昵称、头像、简介可改 |
| R8 | 安全：密码 BCrypt 加密、任何接口不回传密码、写操作需 JWT 鉴权 |
| R9 | 默认排序：店铺与点评列表在无显式排序参数时分别按点评数倒序、时间倒序 |

## 5. 非功能需求（MVP 级）

| 维度 | 要求 |
|---|---|
| 性能 | 单库 MySQL 即可承载 MVP 流量；列表分页统一使用 MyBatis-Plus 分页插件；通过冗余计数与索引避免大表实时 COUNT 与 filesort |
| 安全 | JWT 无状态鉴权；密码 BCrypt；统一全局异常处理，不向客户端泄露 SQL/堆栈；CORS 白名单，仅允许前端开发与生产域名 |
| 兼容性 | 后端 Java 17 + Spring Boot 3.2；前端现代浏览器（Chrome/Edge 最新两个大版本）；移动端响应式 |
| 可维护性 | 前后端分离，REST + JSON；统一返回体 `{code, message, data}`；接口统一 `/api/v1` 前缀 |
| 可用性 | 不引入 Redis/MQ；写入事务保证计数一致性；软删除使用 `status` 字段，保留数据 |

## 6. MVP 范围边界

### 6.1 MVP 必做

- 上述 6 大模块的全部 P0 功能项
- 用户注册/登录（账号密码）
- 店铺 列表/搜索/详情/分类
- 点评 发布/列表（文字+评分+图片）
- 点赞/评论/取消点赞
- 关注/取关/关注列表/粉丝列表
- 首页热门店铺+热门点评，按城市筛选
- 图片上传（OSS，本地存储兜底）

### 6.2 MVP 明确不做（后续版本评估）

> v2 起按 [`docs/06-中间件升级开发计划.md`](06-中间件升级开发计划.md) 逐项转正：已落地 **Redis 点评审热度排行**（Phase A，对应本表第 3 项的部分，详见 `CLAUDE.md`「Hot review ranking」）、**管理员角色鉴权 + 店铺乐观锁**（Phase B，对应本表第 7、8 项的部分，详见 `CLAUDE.md`「Admin role & optimistic lock」）与 **店铺删除延时清理（物理删 + RabbitMQ）**（Phase C / C-Full，对应本表第 3、4 项的删店级联部分，详见 `CLAUDE.md`「Shop delete MQ cleanup」）；管理员占位账号与提权流程见 `db/data.sql` 注释。Elasticsearch+Canal 搜索仍见 `docs/06`，前端配套见 `docs/07`。

1. 复杂推荐算法、个性化推荐、协同过滤
2. 关注 feed 流、动态推送、timeline 拉模式
3. Redis 缓存、热点计数异步化、消息队列
4. 嵌套评论、楼中楼、评论点赞、@提及
5. Elasticsearch 全文搜索（MVP 用 LIKE）
6. LBS 地理位置筛选（MVP 仅按城市字符串）
7. 管理后台、内容审核工作流、多角色权限、商家入驻
8. 用户创建/编辑店铺（MVP 店铺由系统维护）
9. 第三方登录、短信验证码、实名认证
10. 站内私信、通知系统、互动消息推送
11. 积分、等级、勋章、贡献值体系
12. 店铺收藏、想吃清单、打卡
13. 支付、订单、座位预订
14. 接口限流/熔断、全链路监控、容器化、多端（仅 Web）

> 该清单需随需求迭代逐条评估升级，更新本文档版本号。

## 7. 核心用户场景

| 场景 | 主流程 |
|---|---|
| 新用户注册并首次点评 | 注册 → 登录 → 浏览店铺 → 进入店铺详情 → 发点评（上传图片+打分+文字）→ 提交 |
| 浏览消费 | 访问首页 → 按城市筛选热门店铺/点评 → 进入店铺详情 → 浏览点评列表 → 翻看评论 |
| 互动 | 登录 → 查看某点评 → 点赞 → 发表评论 → 关注点评作者 → 在作者主页查看其点评 |
| 维护个人资料 | 登录 → 进入「我的」→ 上传新头像/改昵称/改简介 → 保存 |
