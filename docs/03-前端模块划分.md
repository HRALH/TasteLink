## 1. 前端技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | React 18 + Vite | SPA，Vite 脚手架，HMR 快速开发 |
| UI 组件库 | Ant Design 5 | 表单/列表/分页/上传/消息等组件齐全 |
| 全局状态 | Zustand | 轻量，存登录态/用户信息/Token |
| 路由 | React Router v6 | 按模块分路由 + 路由守卫 |
| 请求 | axios | 封装 baseURL + JWT 拦截器 + 统一错误 |
| HTTP | REST + JSON | 统一前缀 `/api/v1`，遵循后端契约 |

## 4. 页面与路由规划

| 路由 | 页面 | 是否需登录 |
|---|---|---|
| `/login` | 登录 | 否 |
| `/register` | 注册 | 否 |
| `/` | 首页（热门店铺+点评，支持城市筛选） | 否 |
| `/shops` | 店铺列表（搜索/分类/城市筛选） | 否 |
| `/shops/:id` | 店铺详情 + 点评列表 | 否 |
| `/shops/:id/review` | 发布点评 | 是 |
| `/reviews/:id` | 点评详情 + 评论 | 否 |
| `/users/:id` | 用户主页（资料+点评） | 否 |
| `/users/:id/followings` | 关注列表 | 否 |
| `/users/:id/followers` | 粉丝列表 | 否 |
| `/me` | 我的（资料+编辑） | 是 |
| `/admin/shops` | 店铺管理列表（v2，需管理员） | 否（登录+管理员） |
| `/admin/shops/:id/edit` | 店铺编辑（v2，需管理员） | 否（登录+管理员） |

**路由守卫**：需登录页未登录时重定向至 `/login`，并携带 `redirect` 参数以便登录后回跳。管理员路由（`/admin/**`）走 `RequireAdmin`：未登录跳 `/login`，登录但非管理员跳 `/`；真正鉴权仍由后端 `/admin/**` 的 `hasRole('ADMIN')` 强制（非管理员得 403），前端 `isAdmin` 仅为 UI 显隐/前置拦截。

## 5. 请求层与状态管理

### 5.1 axios 封装（`api/request.ts`）
- `baseURL` 从环境变量读取，dev 指向后端 `http://localhost:8080/api/v1`（可经 Vite 代理避免 CORS，二选一）。
- **请求拦截器**：若 `authStore` 中有 token，自动注入 `Authorization: Bearer ${token}`。
- **响应拦截器**：
  - 正常返回取 `response.data`（即后端 `R` 统一结构）。
  - `code ≠ 0`：AntD `message.error(message)` 并 reject（统一 `ApiError`，携带 `code`/`data`）。
  - **可处理码**（`PROCESSABLE_CODES`，如乐观锁冲突 `SHOP_VERSION_CONFLICT=409`）：抑制自动 toast，抛 `ApiError(code)` 交调用方分支处理（如编辑页弹「加载最新内容」）；`409` 以 HTTP 409 传输，在错误分支处理。
  - HTTP 401：清除登录态 → 跳转 `/login`。
  - 网络错误：统一异常提示。

### 5.2 Zustand（`store/authStore.ts`）
- 状态：`token`、`userInfo`（userId/username/nickname/avatarUrl）、`role`（'USER'\|'ADMIN'，可空）、`isLoggedIn`。
- token/userInfo/role 持久化到 `localStorage`，刷新页面恢复；旧持久化态经 `rehydrateRole()` 从 JWT 回填 `role`。
- 动作：`login(token, userInfo)`（顺带从 JWT 解出 `role`）、`logout()`、`updateProfile(partial)`、`rehydrateRole()`。
- 派生：`useIsAdmin()` / 页面内 `(s) => s.role === 'ADMIN'`。
- **role 来源**：v2 后端 `LoginVO`/`UserVO` 未在响应体返回 `role`，仅 JWT claim 携带，故前端经 `utils/jwt.ts` 解码（client 仅用于 UI 显隐/守卫，鉴权仍由后端 `/admin/**` 强制）。

### 5.3 数据获取约定
- 列表分页依据后端 `PageResult{records,total,current,size,pages}`，前端用 AntD `Pagination` 对接 `page`(从1起)/`size`。
- 图片统一先调 `POST /api/v1/files/image` 拿 `url`，再随表单/点评提交。

## 7. 前端协作约定

1. **接口契约**：严格遵循 `05-接口API设计.md`；后端契约变更需先更文档，前端同步适配。
2. **鉴权**：token 注入 `Authorization: Bearer`，写操作需登录；401 统一清登录态跳登录。`/admin/**` 需管理员：前端 `RequireAdmin` 守卫 + 顶栏入口仅 `isAdmin` 可见，后端 `hasRole('ADMIN')` 强制 403；`role` 由 JWT 解出（见 5.2）。
3. **环境**：dev `baseURL=http://localhost:8080/api/v1`，或用 `vite.config.ts` 代理转发避免直连跨域。
4. **图片**：不直传 OSS，统一走 `/api/v1/files/image` 拿可访问 URL 后再使用。
5. **时间**：直接展示后端 `yyyy-MM-dd HH:mm:ss`，必要时前端兜底格式化。
6. **错误**：依赖后端 `message` 提示，不自行推测业务错误语义。
7. **分页**：统一 `page`/`size` 参数与 `PageResult` 结构。
