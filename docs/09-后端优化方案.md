## B1 — 安全(P0,最先做)

### B1-1 Local 存储路径穿越(可删任意文件) ✅ `f727073`
- **链路**:`ReviewServiceImpl.createReview`(`:123-137`)原样入库用户提交的 `imageUrls` → 删店清理时 `LocalFileStorageServiceImpl.ossKeyFromUrl`(`:71-78`)仅做前缀剥离 → `delete()`(`:63`)`resolve("../../x")` 无 normalize,越出 base 目录删文件。
- **修法(三连)**:
  1. 入库校验:`createReview` 的每个 imageUrl 必须以当前 storage 的 URL 前缀开头(`FileStorageService` 增加 `isOwnedUrl(url)` 默认方法,local/oss 各实现),否则 400。
  2. 删除防御:`LocalFileStorageServiceImpl.delete` 内 `resolve(ossKey).normalize()` 后必须 `startsWith(basePath)`,越界拒绝并 `log.warn`。
  3. 治本:`ReviewServiceImpl:133` 把 `oss_key` 真实入库(upload 返回的 `FileUploadVO.ossKey`),清理路径直接用列值而非 URL 反推;`ShopCleanupServiceImpl:31` 的「入库多存空串」注释随之删除。
- **验证**:新增单测覆盖恶意 URL(`../../etc/`)被拒 + 正常 URL 可删;`ShopCleanupIT` 回归。

### B1-2 登录防爆破 ✅ `b96570d`
- **现状**:`AuthController` / `UserServiceImpl.login` 无限流;BCrypt cost=10 使每次撞库尝试都烧 CPU(可被当慢速 DoS)。
- **修法**:Redis 滑窗限流——`INCR login:fail:{username}` + 首击 `EXPIRE 600`,≥5 次拒绝(429/业务码);登录成功清零。**注意独立于 `RANK_CACHE_ENABLED`**(该开关只管热榜);Redis 缺席时降级放行 + warn,不因限流器故障锁死登录。
- **验证**:Mockito 单测(模拟计数达到阈值)。

### B1-3 JWT 密钥 fail-fast + 吊销能力 ✅ `75abbd3`
- **现状**:`application.yml:92` 有提交在仓库的弱默认值 `change-me-please-...`,忘配环境变量即全员可伪造 token(含 ADMIN);无 jti、无登出黑名单,封号/改密后旧 token 24h 内仍有效(`JwtAuthFilter` 不查库校验用户状态)。
- **修法**:
  1. `JwtConfig` 启动校验:secret 为默认值或长度 <32 时,非 local profile 直接拒绝启动。
  2. 加 `jti` claim + `POST /auth/logout`:Redis `SETEX blacklist:{jti}` 剩余 TTL;`JwtAuthFilter` 命中黑名单即 401。Redis 缺席时 logout 降级为仅前端清态(文档注明)。
- **验证**:单测覆盖 fail-fast 分支与黑名单命中;改密码后旧 token 失效用例。

### B1-4 上传魔数校验 ✅ `cc6b413`
- **现状**:`UploadUtil.validateImage` 只看扩展名白名单。
- **修法**:读文件头比对 JPEG/PNG/WebP/GIF 魔数签名,伪装内容(HTML/webshell 改名 .jpg)拒绝。local 模式下该文件会经 `/static/uploads/**` 直接可访问,属存储型 XSS 面。
- **验证**:单测(真图通过、文本改名图拒绝)。

### B3-2 cleanup 事务瘦身 ✅ `60a6621`
- `ShopCleanupServiceImpl.java:50-87`:`@Transactional` 内循环删 OSS 图 + 循环写 Redis,DB 连接与行锁被网络 IO 拉长。
- **修法**:DB 级联物理删留在事务内;`fileStorageService.delete` 与 `hotRankService.onDelete` 收集到列表,`afterCommit` 再执行(与 Phase A/C 既有 afterCommit 模式一致)。失败靠下一轮对账重清(幂等已具备)。

### B3-3 其它 ✅ `1ff33f5`
- `ReviewServiceImpl:126-136` 点评图片逐张 INSERT → `saveBatch`(最多 9 张,顺带与 B1-1-③ 一起改)。

## 提交纪律

- 单批次单 commit,message 形如 `feat(backend): B1-1 上传 URL 白名单+删除路径越界防御`。
- 涉及 API/错误码变更必须先改 `docs/05` 并在同 commit 同步前端 `src/api/*`。
- 涉及表结构变更必须同步 `db/schema.sql` + `docs/04`。
- 敏感信息不入库(凭据走 `application-local.yml` / 环境变量)。
- 完成一个批次在本文档打勾并标注 commit hash。
